## Brand & Style

### Brand Personality & Mood
ProfPing answers one question quickly: *is my professor available right now?* The interface is calm, clear and trustworthy, built for students glancing at a phone between classes and for administrators scanning dashboards. A cool violet identity sits on soft lilac-tinted surfaces, and one set of unmistakable status colors does the real communication. Nothing decorative competes with the status.

### Design Movement & Aesthetic
The style blends **Clean Academic Minimalism** with **Signal-First Design**. It relies on:
- Neutral, softly tinted surfaces so the four status colors are the loudest thing on screen.
- Pill-shaped status chips and buttons that read instantly, even at small sizes.
- Generous spacing and tabular numbers for the dashboards, so desk-hour figures are easy to compare.
- Color is never the only signal: every status also has a text label and an icon.

## Colors

### Palette Architecture
- **Primary (`#492FB1` - Campus Violet):** The brand anchor. Used for primary buttons, active navigation, links, focus rings and selected tabs. It sits well away from every status color, so brand color is never mistaken for a status.
- **Secondary (`#7A4D89` - Muted Plum):** Used sparingly for secondary highlights, selected filter chips (`secondary-container`) and department tags.
- **Tertiary (`#0A687B` - Insight Teal):** Reserved for analytics: chart accents, trend indicators and dashboard highlights.
- **Error (`#BA1A1A`):** System errors only (failed update, login error). It is deliberately different from the "Off Campus" status red, which is not an error.
- **Neutral (`#1A191F` - Ink):** Headlines and body text. A soft near-black rather than pure black.

### Status Colors (the core of the product)
| Status | Fill | Text on fill | Chip background | Chip text |
|---|---|---|---|---|
| Available | `#15803D` | `#FFFFFF` | `#DCFCE7` | `#14532D` |
| Busy | `#F59E0B` | `#1C1917` | `#FEF3C7` | `#78350F` |
| In Lecture | `#2563EB` | `#FFFFFF` | `#DBEAFE` | `#1E3A8A` |
| Off Campus | `#DC2626` | `#FFFFFF` | `#FEE2E2` | `#7F1D1D` |

Rules:
- Each status always appears with a label and an icon, never color alone (suggested icons: check-circle, clock, book-open, map-pin-off).
- Busy uses dark text on amber, because white text on amber fails contrast.
- A small status dot needs a 2px ring in the status's chip-text color so the amber dot stays visible on light backgrounds.
- Status colors are never used for decoration or branding.

### Surface System
- **Background Canvas:** `#FAF8FE` (Whisper Violet), the default app background.
- **Card Surfaces:** pure white `#FFFFFF` (`surface-container-lowest`) on the canvas, separated by a 1px `outline-variant` border or a very soft shadow.
- **Muted Surfaces:** `#EFECF6` / `#E9E7F1` for inactive chips, search fields, table header rows and progress tracks.

### Data Visualization
- **Desk-hour charts** use the status colors directly (green for Available, amber for Busy, blue for In Lecture, red for Off Campus) so charts match what users see in the app.
- **Comparison charts** (departments, faculty) use the categorical set `chart-1` to `chart-5`: violet, teal, plum, amber and slate.
- Add value labels or patterns to charts so they work for color-blind users.

### Accessibility (checked contrast ratios)
| Pair | Ratio |
|---|---|
| Text on surface (`on-surface`) | 16.6:1 |
| Secondary text on cards (`on-surface-variant`) | 7.7:1 |
| White on primary | 9.0:1 |
| Status fills with their text | 4.8 to 8.1:1 (all at least 4.5:1) |
| Status chip text on chip background | 8.2 to 8.5:1 |
| Borders and icons (`outline` on surface) | 4.6:1 |

## Typography

### Structural Choice
**Inter** is used throughout. It is highly legible at small sizes, has tabular numerals for tables and metrics, and loads easily in both Expo (`@expo-google-fonts/inter`) and Next.js (`next/font/google`).

### Editorial Hierarchy & Treatment
- **Screen titles:** `headline-lg` (28px, bold) on web and `headline-lg-mobile` (24px) on phones. The login hero can use `headline-xl`.
- **Faculty names:** `headline-sm` (17px, semibold). Department and designation sit below in `body-md` using `on-surface-variant`.
- **Status chips and button labels:** `label-md` or `label-lg`, semibold.
- **Custom status messages:** `body-md`, up to two lines, truncated after that.
- **Timestamps ("Updated 2 min ago"):** `body-sm` in `on-surface-variant`.
- **Dashboard metrics** (desk hours, counts): `metric-lg` with tabular numerals so columns align.

## Layout & Spacing

### Layout Architecture
- **Mobile first:** a single column with a bottom navigation bar. The faculty screen is built around four large status buttons within thumb reach.
- **Tablet and desktop (dashboards):** a left sidebar plus a content area on a 12-column grid, maximum content width `1200px`.
- **Student directory:** a vertical list of faculty cards with a pinned search field and horizontally scrolling department filter chips.

### Spacing Rules
- **Component Padding:** cards use `space-md` (16px) padding on mobile and `space-lg` (24px) on desktop.
- **Interactive Control Spacing:** buttons and inputs use `space-md` vertical and `space-lg` horizontal padding. Minimum touch target is 48x48px.
- **List Rhythm:** faculty cards are separated by `space-sm` (8px) to `space-md` (16px).

## Elevation & Depth

Depth is kept light so the status colors stay the focus.

1. **Flat Level (cards, table rows, list items):** no shadow, a 1px `outline-variant` border on white.
2. **Raised Level (interactive cards on tap, dropdowns):** `0 6px 18px -4px rgba(73, 47, 177, 0.10), 0 2px 6px -2px rgba(26, 25, 31, 0.06)`. The faint violet tint matches the brand.
3. **Floating Level (bottom navigation, modals, toasts):** `0 12px 28px -6px rgba(26, 25, 31, 0.20), 0 4px 10px -2px rgba(26, 25, 31, 0.10)`.

On React Native, approximate these with `elevation` on Android and `shadowColor`, `shadowOpacity` and `shadowRadius` on iOS.

## Shapes

- **Buttons, status chips and filter chips:** fully pill-shaped (`border-radius: 9999px`).
- **Cards and panels:** `1rem` (16px).
- **Modals and bottom sheets:** `1.5rem` (24px) on the exposed corners.
- **Inputs:** `0.75rem` (12px), or full pill for the main search field.
- **Avatars:** circles. Use initials, not photos, since ProfPing stores no images.
- **Checkboxes:** `6px` rounded squares.

## Components

### Faculty Status Selector (faculty screen)
- Four large pill buttons, each showing the status color, icon and label (Available, Busy, In Lecture, Off Campus).
- **Unselected:** `*-container` background with `on-*-container` text and icon.
- **Selected:** solid status fill with its on-color text, a check icon and a 2px outer ring in the same color. Tapping scales down to `0.98`.
- An optional message field sits below (up to 140 characters, with a live counter) and a "Last updated" timestamp under it.

### Faculty Card (student directory)
- White card with a circular initials avatar, the status dot (with ring) at the avatar's bottom-right, the name, the department and a status chip.
- If the faculty member left a message, it shows in `body-md` below the name, in `on-surface-variant`.

### Chips & Filters
- **Department filter chips:** muted `surface-container-high` when inactive; `secondary-container` with `on-secondary-container` text when selected.
- **Status chips:** the container and on-container pair for the matching status, always with an icon.

### Buttons
- **Primary:** solid `primary` pill with white `label-lg` text.
- **Secondary:** `primary-container` pill with `on-primary-container` text.
- **Text button:** `primary` text, no background.
- **Destructive (log out, remove):** outlined with `error`.

### Inputs & Form Fields
- Background `surface-container-low`, with a 1px `outline-variant` border. The focused state uses a 2px `primary` border. Error state shows a 2px `error` border with the message beneath in `error`.

### Navigation
- **Mobile:** a floating bottom bar with an active pill in `primary-container`.
- **Web:** a left sidebar with the active item in `primary-container`, and a role label (HOD or Principal) at the top.

### Dashboard Components
- **Live Status Table:** header row in `surface-container-high`, 1px row dividers, a status chip in each row and a "last updated" column.
- **Metric Card:** white card with a `label-md` caption, a `metric-lg` value and a small trend indicator in `tertiary`.
- **Charts:** white card, a title in `headline-sm`, a legend using the status or chart colors, and a gridline color of `outline-variant`.

### System States
- **Loading:** skeleton blocks in `surface-container-high`.
- **Empty:** a muted icon with one line of `on-surface-variant` text.
- **Offline or sync issue:** a banner in `surface-container-highest` with an `outline` border, which is not red because being offline is not an error.
- **Error toast:** `error-container` with `on-error-container` text.

## Implementation Notes

- Store all tokens once in `packages/shared/src/theme.js` and import them in both apps: the web app through the Tailwind config (`theme.extend.colors`) and the mobile app in `StyleSheet` objects.
- Update `packages/shared/src/constants.js` to use these status values, especially Available (`#15803D` replaces `#16a34a`, which has lower contrast with white text).
- Load Inter with `@expo-google-fonts/inter` on mobile and `next/font/google` on web.
- A dark theme can be added later by mapping each token to a darker tone. It is not part of this version.
